## 1. Requirements that constrain the base image

- **[REQ] DG §2, §9.** Recommended base `vllm/vllm-openai:v0.10.1.1` (tested with PyTorch 2.7.1+cu128). An alternative must support RTX 5090, compute capability 12.0 (CUDA ≥ 12.8, matching PyTorch and vLLM).
- **[REQ] DG §9 step 4.** Reset `ENTRYPOINT []`. `NCCL_P2P_DISABLE=1`. The sample used `nvidia-nccl-cu12==2.27.7` to fix a two-GPU **tensor-parallel** initialization hang; "validate this workaround with your stack".
- **[REQ] DG §2.** Uncompressed `docker save` tar ≤ 100 GB. The DG sample image (Qwen3-14B bf16, 28 GB of weights) measured 50.5 GB, so the reference base image is roughly 20–25 GB **[OBS from DG figures, not measured here]**.
- **[REQ] SPEC §4.4.** `requirements.lock` is generated by `pip freeze` inside the chosen base image after installing project requirements; development installs from the same lock.
- **[OBS]** The inference package needs only `duckdb` and `pydantic` v2 beyond the base image (`pyproject.toml`). `pydantic`, `transformers`, `openai` and `torch` come from the image. `HttpModelClient` uses only the standard library.

## 2. Reference image: `vllm/vllm-openai:v0.10.1.1`

Facts taken from the DG: vLLM 0.10.1.1, PyTorch 2.7.1+cu128, validated by the organizers on RTX 5090 pairs (compute capability `(12, 0)`, no P2P). **[PROPOSE]** use it unless a candidate model needs a newer vLLM, because it is the only image the organizers state they tested, and the organizers' re-run uses their own driver stack.

## 4. Producing `requirements.lock`

```bash
tools/gen_requirements_lock.sh vllm/vllm-openai:v0.10.1.1
```

The script (build host with Docker and network; **not** the offline run) pulls the image, freezes the untouched image (`requirements.lock.base`), installs `requirements.in` under those pins as constraints so pip cannot replace torch or vllm, freezes again (`requirements.lock`) and records image id, repo digest, Python, torch, CUDA and vLLM versions (`requirements.lock.meta.json`). Its output is never edited by hand.

**Status 2026-11-11: not yet generated.** Docker exists on the development machine, but the reference image is not cached locally (`docker images` lists no vLLM or Python base image), the root filesystem has about 17 GB free, and pulling a roughly 20 GB image is a download the hand-over rules did not authorize. Acceptance (`pytest` passes when installed from the lock, TASKS M4-01) therefore remains open. Run on the build host:

```bash
tools/gen_requirements_lock.sh
python3 -m venv /tmp/lockcheck && /tmp/lockcheck/bin/pip install -r requirements.lock.base -r requirements.lock --no-deps  # heavy: GPU wheels; prefer running pytest inside the image instead
docker run --rm --entrypoint "" -v "$PWD":/src:ro vllm/vllm-openai:v0.10.1.1 bash -c 'cp -r /src /tmp/w && cd /tmp/w && pip install -e . --no-deps -r requirements.in && pip install pytest && python -m pytest'
```
