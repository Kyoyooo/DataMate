## Public APIs

```python
from pathlib import Path
from datamate.catalog import setup_business, load_catalog, save_catalog, make_fake_catalog
from datamate.config import RunConfig

cfg = RunConfig(work_dir="out/m1/work")
catalog = setup_business(Path("data/train/train/data/<business>"), "<business>", cfg)
assert catalog.status == "ready", catalog.warnings
save_catalog(catalog, Path(catalog.db_path).parent / "business_catalog.json")

fake = make_fake_catalog(Path("out/m1/fakes"), "sales")
```

The third argument also accepts the former work-directory argument for existing
callers. Catalogs contain the database path, original headers, typed/raw column
links, parse rates, observed unit suffixes, profiles, candidate keys/joins,
date columns/range, complete README, full SchemaCard/hash, setup time, warnings
and status. Read-only query views exclude identified structural rows; source
duplicates, grouped cells, business statuses and units are not normalized away.

Raw values altered by typing are exposed beside typed columns as `<name>__raw`.
Per-value status and source-row fields permit audits without interpreting NULL
as zero. DB files and output metadata are written outside the input directory.
An unrelated undelimited TXT file is skipped with a warning, not a business-wide
failure. Setup failures return a failed catalog so existing orchestration emits
`E_BUSINESS_SETUP` abstentions.

Contracts advance from bootstrap **0.1.0 to 0.2.0** for M1. New M1 boundary models
are frozen, strict and reject unknown fields. Top values serialize as
`{value,count}` objects and warnings as `{code,detail}`. Explicit adapters accept
legacy top-value pairs/warning strings. Existing optional fields retain defaults.
The full cross-team SPEC 1.0 migration is not falsely declared complete.
Consumer review is needed before merging these shared-interface changes.

JSON schemas are under `contracts/schemas/`. Regenerate with
`tools/export_m1_schemas.py`; snapshot tests catch drift. Rebuild fake artifacts
with `tools/build_m1_fixtures.py`. The fake builder inserts explicit typed values
and never invokes source ingestion.

temporal reasoning must use the relevant date column when asking about future
expiry/deadline windows, rather than treating activity coverage as their range.

Training revealed genuine ambiguous numeric surfaces; these remain VARCHAR
under SPEC policy. Date columns without enough valid values likewise retain
their source representation instead of receiving invented dates. Warnings,
original values and statuses stay available to downstream reasoning and gating.

Entity values are returned exactly as stored, with accents retained. Folded keys
are internal retrieval metadata only. A code is attached only when the name/code
mapping in that table is unambiguous. Fuzzy scores are relevance, not correctness
probabilities.

Semantic DDL must be one declared `CREATE VIEW v_* AS SELECT ...`, with actual
known main-schema dependencies. It cannot create/modify source tables, access
external files or self-certify validation. Failed, empty, duplicate-key,
unproven-exclusion or category-disabled views remain disabled and are logged.
All model response/reasoning records come directly from `ModelClient`; unit
responses are explicitly synthetic test doubles.

`tools/evaluate_m1_gate.py` consumes real off/on prediction files and an explicit
training-held-out manifest after M3 is available. The manifest must declare
effective off/on `RunConfig` values, source role `train`, and folds containing
`held_out_business_ids`, `training_business_ids`, optional `fewshot_business_ids`
and exact `question_ids`. Entire businesses must be held out and no held-out
business may appear in few-shot/training sources. Entity linking must not lower
PA; compiled views must improve it. Categories are reported only if supplied by
training; the actual training questions currently have no category field. No
gate automatically enables a feature.

## Design notes and verification boundaries

- The SPEC header score alone can rank a later all-text data record above a
  real header whose following values mix strings and numbers. Confirmed whole
  header labels restrict the candidate set before applying the documented score.
  This safeguards actual training exports and is documented rather than hidden
  as an ID-specific exception. Product/note contents are not treated as header
  hints simply because they contain words such as `giá` or `tên`.
- Date-year hints use a single unambiguous year in the sheet first, then filename;
  their source text is persisted. No current-year or training-rulebook constant
  is used as a universal rule.
- Physical SQLite source-directory read-only behavior is covered by a POSIX CI
  test. The local Windows run verifies immutable URI behavior/source hashes but
  skips POSIX chmod enforcement. A Linux container run remains a separate check.
- Schema token budgets are certified only with an actual supplied tokenizer.
  Low-cardinality values are retained; high-cardinality examples shrink first.
  Relevant-subset selection retains complete columns for up to four tables and
  names the others; remaining overflow becomes `E_CONTEXT_OVERFLOW` abstention.
- No real model, generated answers, held-out PA claim or Docker submission was
  produced. P2 accuracy acceptance remains deferred with M3 as requested.
- Notebook files retain their earlier embedded snapshots. Updating them is a
  later synchronization task, explicitly excluded from this request.
